# 拟合定数校准：2026-09-06 快照回放

## 目的与数据

本次改进把 B20 从“每张谱面都应该达到的 rating”改为玩家分组依据，先减去同实力差距、相近官方定数的其他谱面上常见的反推偏差，再保留目标谱面的剩余差异。官方定数提供坐标与先验，主观投票用于校验差异方向、确定合理幅度，不直接覆盖任何谱面的结果。

本地输入：`data/backup_202609061430.dump` 和 `data/主观定数总表.xlsx`。过滤软删除行后，共 1,278 张谱面、471,340 条最佳成绩、5,327 位玩家。提取程序只读取歌曲、谱面、最佳成绩与成绩表，不读取账号表，也不执行 dump 中的 SQL。中间文件用整数替换用户名，不应提交。

投票按曲名和难度精确匹配：`[RBT]` 为 reboot，`[MSV]` 和无后缀为 massive。成功匹配 227 张；15 条 CTC、同名歧义或未匹配记录不猜测对应关系。票数是汇总结果，不是可重新采样的独立玩家投票；正文以每谱等权指标为主，脚本另报按票数加权 MAE。

## 对照方法

- 旧 B20 / 旧 B50：相同权重、先验、截断参数，仅改变玩家 top-K。
- 校准未缩放：排除目标谱面，按官方定数和实力差距估计背景残差；保留原有鲁棒聚合与收缩。
- 新 B20：在上述结果相对官方的差值上乘 `calibration_scale=0.1`。
- 官方基线：始终使用官方定数。这一基线不能识别虚高虚低，但可检验拟合是否只是增加噪声。

所有误差对照使用四种拟合方案均有输出且有投票的 **225 张共同谱面**，避免因弃算较难谱面而夸大改善。按 `song_id % 5 == 0` 留出 47 张，其他 178 张用于估计残差幅度；同一首歌的不同难度留在同组。训练集上无截距最小二乘的幅度系数为 **0.09155**，取可解释的默认值 **0.1**。

这是探索算法后的回顾性分组验证，并非预注册的盲测，也没有时间外推测试。留出的是主观标签；所有可用成绩和官方定数仍用于无监督背景校准。B20 本身仍包含该玩家的目标成绩，不应把本方法称为完全独立的留一交叉拟合。

## 结果

| 方案 | 全库发布数 | 全库平均偏差（拟合−官方） | 共同谱面投票 MAE | 留出投票 MAE |
|---|---:|---:|---:|---:|
| 旧 B20 | 421 | +0.26001 | 0.29222 | 0.26930 |
| 旧 B50 | 481 | +0.02251 | 0.16310 | 0.17380 |
| 校准 B20，幅度 1 | 416 | −0.00550 | 0.12118 | 0.10354 |
| **校准 B20，幅度 0.1** | **416** | **−0.00055** | **0.02774** | **0.02489** |
| 官方基线 | 1,278 | 0 | 0.03086 | 0.02938 |

新方案 193 张上调、223 张下调。该比例不是算法约束，算法没有强制总偏差为零，也没有强制上下调数量相等。相对旧 B20，发布数净减少 5 张；相对旧 B50，覆盖减少 65 张，因此不能只报告误差而忽略覆盖。

在主观−官方绝对差至少 0.03 的 97 张共同谱面中，方向一致率从旧 B20 的 **49.5%** 提高到 **73.2%**；留出组只有 16 张达到阈值，方向一致率为 **68.8%**。全共同集的“拟合−官方”与“主观−官方”相关系数为 **0.432**，留出组为 **0.529**。这比直接比较绝对定数的相关性更能检验虚高、虚低信号。

以歌曲为单位对留出组做 2,000 次配对 bootstrap（固定种子 20260906），相对官方基线的 MAE 改善约为 **0.00449**，95% 百分位区间约 **[0.00103, 0.00798]**。该区间不包含算法选择、投票测量误差和未来版本变化的不确定性。

| 鵺 | 15.500 | 15.408 | 15.712 | 15.487 |
| Aleph-0 | 16.500 | 16.591 | 17.190 | 16.549 |
| Cybernetic Vampire | 16.700 | 16.784 | 17.113 | 16.724 |
| Inner Norm | 15.400 | 15.475 | 16.049 | 15.428 |
| Xenolith | 14.800 | 14.957 | 15.069 | 14.794 |
| Take On The H.E.A.T.!!! | 15.000 | 15.092 | 15.268 | 14.997 |

最后两张仍与主观方向相反。新算法不能消除玩家偏科、反复练习、选曲自选择和成绩上传时机的影响；主观投票也不是无误差真值。0.1 的幅度参数是这批投票支持的保守范围，不是游戏难度的物理常数。对于低定数、缺少投票的范围，这个幅度属于外推，应随新数据复核。

默认先截断再缩放，因此最终偏离官方的硬上限为原 cap 的 10%：低端 ±0.06，高端 ±0.15。这也意味着当前方案会低估个别严重标错的谱面；如需放大差异，应在新增独立投票上重新校准，不能只为几个例子提高系数。

## 复现

需要 Go、`pg_restore`、Python 和只读提取用的 `openpyxl`。

```bash
python3 scripts/fitting_snapshot.py \
  --dump data/backup_202609061430.dump \
  --votes data/主观定数总表.xlsx \
  --output /tmp/fitting-snapshot.json

go run ./cmd/fitting evaluate \
  --snapshot /tmp/fitting-snapshot.json \
  --output /tmp/fitting-evaluation.json

python3 scripts/fitting_evaluate.py /tmp/fitting-evaluation.json
```

`evaluate` 不连接数据库、不加载生产配置，固定使用代码默认参数（时间衰减关闭），输出每谱统计与四组结果。生产运行仍用 `fitting run`；已有配置中显式设置的 `skill_top_k` 不会被覆盖，应明确设置为 20 以复现本报告。回退原算法可设置 `calibration_enabled: false` 并保持原来的 top-K。

线上曲表在本次只读检查中显示 420 张有拟合值，388 张偏高，32 张偏低，平均偏差 +0.26081；与 dump 回放的差异源于快照/配置时点不同，不将二者混作同一次实验。本次没有写入生产数据库。
